# 宝可梦与地图内容扩展：整理与实施规划

## 目标与范围

让后续添加宝可梦和地图有可维护的数据入口、可重复的验证与发布流程，同时保留现有玩家存档和离线玩法。用户已确定扩展目标均为已有的宝可梦和地图，而非原创内容；具体清单、版本和素材来源仍待盘点。本文是规划，不代表内容扩展接口或工具已经实现；现有架构见 [architecture.md](architecture.md)。本阶段不改游戏规则、不重新编号现有内容、不删除上游压缩包。

## 现状和关键约束

- 游戏运行时主要在 `site/bundle/app.c74e480997.js`，包含物种、剧情及遭遇等数据与逻辑。`site/bundle/lang-zh-Hans.2a57ab3291.js` 和 `lang-zh-Hant.ff6e3ad523.js` 提供中文文本，图片位于 `site/assets/`。
- `scripts/build-offline.cjs` 以当前 `site/` 为基线，在临时副本应用补丁后复制指定产物；它不是从可读源码编译游戏，也不会自动把新增数据文件接入运行时。当前补丁多依赖压缩文本的精确锚点，升级上游包时需要重新验证。
- 玩家进度使用浏览器 localStorage 的 `gachamon-save-v1`；物种、个体和章节的具体存档引用与迁移规则须在实施前核实。不能假设改变 ID、调整章节顺序或删除旧数据是安全的。
- 普通野生遭遇不受天气筛选和权重影响；昼夜和进度等其他条件保留。普通区域面板不按天气分类。不能因为新增内容而破坏这些约定。
- 当前离线缓存只尽力预缓存核心资源，图片通常按需缓存。新增素材不等于首次访问后即可全部离线使用。

## 目标结构（提议）

```text
content/                          # 唯一人工编辑的新增内容来源，待实现
  pokemon/                        # 物种、形态与进化数据
  maps/                           # 地区、章节、节点与遭遇配置
  locales/                        # 简体、繁体文本，以稳定 ID 关联
scripts/content/                  # 校验与生成工具，待实现
site/assets/                      # 运行时素材
site/bundle/app.c74e480997.js     # 现有运行时及生成内容的接入位置
```

目录只是建议，具体文件格式在试点后确定。不要同时手改数据源和生成产物：人工编辑内容源；构建在临时目录验证、生成或注入后，再发布运行时产物。现有压缩包仍作为运行时基线，首期不重写战斗或地图引擎。

### 内容模型和关联

以下是要表达的概念，不是现有运行时已支持的字段清单：

| 内容 | 最小信息 | 主要关联与校验 |
| --- | --- | --- |
| 宝可梦物种 | 稳定 ID、名称、属性、战斗数值、捕获相关数据、素材引用 | ID 不重复；必要数据完整且值合法；运行时支持的能力、招式、成长与稀有度字段须逐项确认。 |
| 形态与进化 | 基础物种、形态标识、进化目标及条件 | 引用存在；形态 ID 不冲突；检查非法循环及条件可执行性，保留游戏支持的合法分支。 |
| 本地化 | 简体和繁体名称及可选介绍 | 与物种 ID 一一对应；缺少介绍时沿用“无介绍／無介紹”，不要把缺失名称静默回退成外文。 |
| 地区与地图 | 稳定地区、章节和节点标识；节点类型、顺序、入口及开放条件 | 节点和章节引用有效；入口可达；确认运行时真正支持的节点类型、顺序及解锁语义后再定义格式。 |
| 遭遇 | 区域节点关联的物种、权重、可用条件 | 物种和条件有效；权重合理；沿用昼夜、进度和传奇过滤，不引入天气筛选或权重。 |
| 素材 | 普通／异色／立绘等实际需要的文件与相对路径 | 校验路径、格式、尺寸和部署大小写；核对素材权利和使用许可；缺图时明确失败或采用已确认的回退规则。 |

**身份原则：**新增内容使用不与现有数据或形态冲突的稳定标识；已发布标识不可复用或随显示顺序变化。先盘点现有 ID、形态和存档结构，再决定命名空间及分配方式。删除、改 ID 或重排节点必须先设计迁移和回滚，不能仅靠校验器保证兼容。

## 实施顺序与交付验收

### 阶段 0：保护现有进度与基线

1. 更正 README 中把 `pokecatch-anon` 写成存档键的问题；核查所有相关键并编写经验证的备份、恢复步骤。
2. 准备不含个人数据的旧版存档样本，记录从加载、捕获、前进、保存到重载的基准行为；对损坏数据和缺失字段单独留样。
3. 执行现有 `scripts/test-*.cjs` 和素材检查；在隔离浏览器验证普通遭遇、区域面板、离线重载。记录环境与未覆盖项。

验收：可恢复的测试存档、通过的基线和已知限制；不对用户真实存档做破坏性测试。

### 阶段 1：盘点运行时数据与接入位置

追踪当前包中 `POKEDEX`、`STORY.CHAPTERS`、`Game.DEX`、`Game.PREVO`、遭遇池和中文数据的定义、初始化顺序及消费者；确认物种 ID、形态、地图节点和章节在存档中的表示。检查图片 URL 构造、地图背景、解锁与图鉴显示。历史研究仅供定位，必须对当前 bundle 重新验证。

交付字段映射和依赖图：每个字段注明来源、用途、必需性、默认值和证据位置；列出 ID 分配、缺图、缺翻译和存档升级的实际行为。明确接入时机必须在相关索引和语言初始化之前，或能安全地重建这些索引；具体时机以试验证据为准。

### 阶段 2：校验与生成管线

先选一种最小可编辑格式，提供单一命令，对重复 ID、引用、字段范围、翻译与素材做确定性校验，错误应包含文件和条目位置；输入不合法时退出非零且不改已发布产物。随后在临时目录生成内容并接入现有构建，验证重复构建结果一致、失败不污染 `site/`。如果接入需要新增脚本或数据文件，更新 `site/boot.js` 加载顺序、部署产物与 `site/sw.js` 的离线策略；若改为注入现有 bundle，也要确保本地构建的幂等性和锚点失效时明确报错。

验收：合法样例可构建；重复 ID、缺失引用、非法权重和缺失必需素材均有负例；构建两次无差异；只靠仓库文件可重建。

### 阶段 3：一个宝可梦纵向试点

先选择不改变现有 ID 的测试物种，用授权或自制素材覆盖名称、介绍、普通／异色显示、战斗、捕获、图鉴、存档和重载；如要试验进化，再选择运行时已支持的进化条件。分别验证简体和繁体，并用旧存档加载新版本。确认数据流和索引有效后再批量扩充。

验收：真实浏览器中可遇见、捕获、查看、保存并重载；缺介绍按约定显示；旧物种与旧存档不回归。试点内容是否进入正式版本由维护者另行决定。

### 阶段 4：一个地图纵向试点

先确认新地区、章节、节点、解锁、背景、普通遭遇及存档进度的真实结构。以一个小型测试区域串通进入、移动、遭遇、面板、存档和重载；确保物种显示属于该区域、无天气分组，不同天气下普通遭遇的可用物种及权重不变。检查昼夜与进度条件仍按原逻辑工作。

验收：新旧地图可进入且进度可恢复；无无效节点、死路或缺素材；新区域切换与离线表现经浏览器验证。特殊区域、传奇和剧情脚本不自动视为已支持。

### 阶段 5：批量内容与发布

为新增内容提供模板和清单，逐批校验平衡、翻译、素材许可和存档兼容。先在隔离浏览器的根路径与子路径测试在线、更新和离线，再部署；记录构建号、源提交、测试结果与可回滚版本。发布期间先解决或明确接受固定 SW 缓存版本导致新旧资源混合的风险。

## 验证矩阵

| 层级 | 必需覆盖 |
| --- | --- |
| 内容校验 | 重复／缺失 ID、引用、必需字段、数值范围、翻译、素材路径；错误可定位。 |
| 构建 | 确定性、幂等、异常中止不覆盖现有产物、干净副本重建。 |
| 游戏逻辑 | 新物种索引、进化、各天气普通遭遇一致、昼夜和进度条件、区域面板物种集合。 |
| 存档 | 新档与旧档加载、捕获后重载、地图进度恢复、升级与回滚；不承诺旧版本能读取未来版本，须实际验证。 |
| 浏览器与离线 | 简繁显示、地图交互、图片请求、刷新、子路径、更新后断网；单次加载不等于所有素材已缓存。 |

## 优先决策与风险

1. **扩展范围：**仅添加已有的宝可梦和地图，不设计原创物种或原创地图。须先确认具体作品、世代及目标清单，并对照当前游戏数据去重。
2. **地图语义：**既有地图可能需要映射到现有地区节点，也可能需要新增游戏内地区或章节；须根据目标清单确认解锁与存档模型，不预先假定其已受运行时支持。
3. **素材来源：**先确定合法授权或自制素材、风格和尺寸，再做批量导入；本项目当前素材权属见 README。
4. **压缩包耦合：**锚点和初始化顺序均可能随包变化。优先做小范围纵向试点，再决定是否逐步抽离可读模块；不要一次重写整个游戏。
5. **存档兼容：**稳定 ID 和旧档样本是前提。任何破坏性迁移须提供备份、失败处理与回滚策略。

以上决策完成前，不假设具体内容字段、ID 范围或地图容量；阶段 1 的实证结果决定最终格式与技术方案。
