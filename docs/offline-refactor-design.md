# 离线适配层模块化设计

## 目标与范围

整理现有单机适配代码，使性能偏好、界面导航、战斗日志、游客后端和版本更新分别维护。保留原站压缩游戏包及其必要接口，保留现有存档和游戏行为。清理经引用检查和运行验证确认不再使用的本地代码、资源引用及展示入口，不根据隐藏状态直接删除游戏核心代码。

## 模块边界

- **性能偏好**：仅在未设置偏好时初始化省电选项，保留用户设置。
- **界面与导航**：统一维护被隐藏的入口、交换导航及必要的 DOM 初始化；保留上游代码仍引用的节点。
- **战斗日志**：监听战斗提示，维护有界日志并处理消息栏重建。
- **游客后端**：独立维护 Supabase 离线替身，不依赖界面初始化。
- **更新检测**：独立负责版本轮询和更新提示。
- **游戏规则补丁**：保留连接绳进化和新游戏倍速的可重复补丁，并在上游格式不匹配时明确失败。

模块加载顺序需保证游客替身先于游戏逻辑、性能默认值先于游戏读取；支持根路径和子路径部署。运行时依赖及 Service Worker 核心缓存同步更新。

## 构建和兼容

将镜像目录改为显式参数或环境变量，提供可理解的错误；不得依赖某台机器的绝对路径。生成内容与维护源保持单一来源，避免构建脚本和已发布代码出现两份手工维护的实现。保留原有 localStorage 键及用户设置，不重置进度。清理之前确认上游代码的事件绑定、DOM 查询和游戏数据引用。

## 实施顺序

以下为待实施计划，并非已完成记录。每一步保持现有执行顺序和游戏行为，完成后再记录实际验证结果。

1. **基线与审查**：运行现有素材、进化和浏览器检查，记录隐藏节点及上游引用。
2. **拆分界面模块**：从 `site/offline-ui.js` 分离性能偏好、导航与战斗日志，验证已有和新偏好、日志 40 条上限、节点异步出现及导航事件。
3. **拆分游客及更新逻辑**：从 `scripts/build-offline.cjs` 抽出 mock 维护源，使 vendor 从同一源生成；验证游客客户端与更新轮询。
4. **可移植构建**：通过参数或环境变量指定镜像目录，路径不存在时明确报错；保留规则补丁与部署路径处理。
5. **测试设施与清理**：浏览器测试使用独立临时配置，启动并清理服务，避免依赖固定浏览器状态；仅移除确认无引用的代码和资源。
6. **回归检查**：检查开局、存档重载、交换导航、日志、设置、子路径及 Service Worker 缓存，运行现有检查并记录未实测的设备性能。

## 验证

建立可重复的测试入口，启动并清理独立 HTTP 服务和浏览器配置；失败时输出清晰诊断。覆盖新旧性能偏好、开局与存档重载、导航及交换页、战斗日志、设置、动态素材和根路径/子路径访问；验证 Service Worker 升级及离线缓存。运行现有进化和素材检查，并对照审查发现逐项确认。设备温度和功耗如无法在目标设备测量，明确记录未验证。
